# 使用说明

写给服务器管理员：怎么把 Bot 装起来、命令怎么用、需要哪些权限、有哪些做不到。

## 准备 Discord 应用

**创建与安装**

1. 到 [Discord Developer Portal](https://discord.com/developers/applications) 创建应用，再创建它下面的 Bot，记下 **Application ID**。
2. 用 OAuth scopes `bot` 和 `applications.commands` 把 Bot 装进要管理的服务器。

**权限**

| 场景 | 操作者需要 | Bot 需要 |
| --- | --- | --- |
| 常规清理 / 检索 | View Channel、Read Message History、Manage Messages | 同左 |
| 清理**同时归档且锁定**的帖子 | 上述三项 + Manage Threads（管理线程） | 同左 |
| 只归档、或只锁定 | 三项即可，不额外要求 | 同左 |

- 权限在目标帖子的**父频道**上检查。
- Administrator 与服务器所有者按 Discord 自身规则判定，但**操作者的权限不会自动传递给 Bot**。
- 命令菜单默认要求 Manage Messages；运行时仍会重新核对目标帖权限——命令可见不代表一定能执行。

**Intent**

只需要普通的 Guilds intent。不需要 Message Content，也不需要 Guild Members。

**获取 ID**

在 Discord「用户设置 → 高级」打开开发者模式，即可右键复制用户、服务器、线程 ID。

帖子内消息链接有两种写法：

```text
https://discord.com/channels/服务器ID/线程ID
https://discord.com/channels/服务器ID/线程ID/消息ID
```

两种都定位到**整个线程**，不会只删链接里那一条。确认前请核对预览范围。

**归档帖的特殊之处**

归档帖无法直接在其中使用 Slash Command。换到同一服务器的其他可用频道执行 `/purge-user`，把帖子链接或 ID 填进 `post` 即可，`/purge-status` 同理。

Bot 只读取状态、删除获准的消息，不会为了干活自动取消归档或解锁。线程状态与权限会在扫描、确认、处理三个阶段各查一次，权限不足即停止。依据：[Discord 官方线程文档](https://docs.discord.com/developers/topics/threads)。

## 命令一览

```text
/purge-user account:用户ID或@用户 post:帖子链接或线程ID
/purge-status task:任务ID
/search-posts forum:论坛频道 keyword:标题关键词 [tags:标签ID]
```

## 清理账号发言

`/purge-user` 找出一个账号在指定帖子里的全部发言，过目后再删。

**匹配方式**：按用户 ID，不受昵称改动影响，已退服账号也能处理。

**扫描**：分页读取完整历史，不只是最近 100 条。必须扫完才给出确认按钮——宁可慢，也不拿不完整的结果开始删。

**预览内容**：目标账号、服务器、帖子、可清理数量、保留数量与处理方式。只有发起者能确认、取消或查询。

**不会被删的东西**：首帖、系统消息、他人发言、其他帖子。删除的只有预览时记下的那批消息 ID，预览之后新增的发言不在范围内。

**删除方式**：两周内每批 2–100 条批量删除；超过两周、或卡在边界上的，逐条删除。老帖会比较慢。

**权限**：检查操作者与 Bot 在目标帖子父频道的权限，确认时和处理过程中各复查一次。重复确认不会重复启动任务。

**隐私**：所有交互回复都是 ephemeral（仅自己可见），并禁用自动提及。日志不含消息正文与凭据。

### 操作流程

1. 运行 `/purge-user`，填入目标账号与帖子。
2. 等扫描结束，核对账号 ID、帖子链接、可清理数量、保留数量，以及「不可恢复」警告。
3. 点「确认删除（不可恢复）」或「取消」。两周前的消息较多时，多等一会儿。
4. 用 `/purge-status` 查询结果或取回按钮。无权限、已过期、重复点击、他人代点都会被拒绝。

## 检索论坛帖子

`/search-posts` 在指定论坛或媒体频道里筛帖子。**只读**，不修改、不删除任何内容。

**标题匹配**：关键词多个时用空格分隔，**全部包含**才命中（AND），不区分大小写。只匹配标题，不搜正文。

**标签筛选**：输入框带自动补全，只列当前论坛的标签。可填多个，逗号分隔，同样**全部包含**。填了不存在的标签会直接报错，不会静默放宽条件。

**结果**：ephemeral 回复，每页 10 条，用「上一页 / 下一页」翻页，只显示标题与跳转链接。保留 **15 分钟**，Bot 重启后失效，只有发起者能翻页。

**权限**：操作者与 Bot 都需要该论坛的 View Channel 与 Read Message History。

**枚举顺序**：先取全服活跃线程中属于本论坛的部分，再按归档时间倒序翻归档公开线程。

### 操作流程

1. 运行 `/search-posts`，选择论坛频道，填写标题关键词，标签可选。
2. 等枚举结束——帖子多的论坛需要几秒。结果按发帖时间倒序，标题可点击。
3. 用按钮翻页。

## 边界与限制

**支持范围**：配置服务器内的论坛帖子与公开线程，含已归档或已锁定的；支持论坛/媒体帖子、文字/公告频道的公开线程。归档与锁定状态保持原样。

**不支持**：整频道清理、私聊、私密线程、普通消息的「引用回复树」。不能把论坛频道 ID 当帖子 ID 用。

**不会代劳**：不自动取消归档、解锁、加人进服务器、改权限，也不删除整个帖子。

**并发**：每帖同时最多一个任务；全局最多两个活动任务（含等待确认的）。

**预览上限**：单次最多扫描 **100,000 条**消息、保存 **50,000 条**候选，最长扫描 **5 分钟**。触及任一上限或分页异常即预览失败，**不会用不完整的结果开始删除**。

**时间限制**：预览完成后 **5 分钟**内要确认。单次删除任务最长 **2 小时**。失败、超时、取消都会保留已处理部分，不谎报全部完成。

**任务记录**：仅在内存，最多 100 条，结束后保留 30 分钟。Bot 重启会丢失任务与按钮状态，也不会自动续删——重新预览即可核对剩余。

**进度更新**：Discord 交互 Token 有效期 15 分钟，自动进度更新最多持续约 14 分钟。更久的任务仍在后台运行，用 `/purge-status` 查询。

**停止任务**：只能取消后续工作。已发出的请求可能仍会完成，已删除的内容无法恢复。

## 关于统计数字

预览结果里的「删除请求成功处理」**不是**精确的新增删除数——批量接口对已不存在的 ID 也可能返回成功。

单条请求明确返回 Unknown Message 的计入「已不存在」。超时或网络失败可能留下不确定结果，它们仍算在「剩余 / 未确认」里。要核对就重新预览，别拿一次请求的计数当审计事实。
